## 2024-04-09 - N+1 optimization candidate in PropertyCard checking favorite status
**Learning:** `PropertyCard.tsx` calls `supabaseService.getFavorites(user.id)` inside a `useEffect` for *every* card rendered on the page to check if it's favorited. For a list of 20 properties, this fires 20 identical API requests/RPC calls to fetch the user's favorites list. This is an N+1 fetching problem on the frontend.
**Action:** Implement a short-lived in-memory cache/promise deduplication pattern directly within `supabaseService.ts` for `getFavorites`, or use a `Map` to cache it so concurrent requests for the same user ID return the same promise. Memory constraints/docs advise in-flight promise deduplication and short-lived caching directly within Supabase service modules to solve frontend N+1 bottlenecks.

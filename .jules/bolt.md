## 2024-05-14 - Optimize Supabase Check Queries
**Learning:** For existence checks in Supabase, using `.select('*').single()` performs a full data fetch which is inefficient when we only care about true/false. Using `.select('id', { count: 'exact', head: true })` does a HEAD request and transfers zero row data, making it faster and saving bandwidth. Or just fetching one small column like `property_id` with `maybeSingle()` instead of `*` is also faster. Actually, `maybeSingle()` with a single column is good. Let's see if we can use `{ count: 'exact', head: true }` with `.limit(1)` or similar. Wait, for existence, if we just want to know if it exists, `count: 'exact', head: true` returns the count. But another memory note says: "For efficient Supabase existence checks (e.g., checking if a record exists to return a boolean), use `.select('id', { count: 'exact', head: true })` instead of `.select('*').single()` to perform an HTTP HEAD request and avoid transferring unnecessary row data."
**Action:** Replace `isPropertyUnlocked`, `toggleFavorite`, and other existence checks using `.select('*').single()` with `.select('id', { count: 'exact', head: true })`.

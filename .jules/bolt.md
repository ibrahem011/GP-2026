## 2024-05-18 - Parallelizing I/O-bound Supabase Storage Operations
**Learning:** Sequential `for...of` loops used for uploading, signing, or deleting multiple files in `supabaseService.ts` create significant artificial latency bottlenecks, as each network request waits for the previous one to complete. While `Promise.all` is excellent for parallelizing uploads and URL signing, error recovery paths (like deleting orphaned uploaded images if a subsequent database insert fails) require `Promise.allSettled` to ensure all cleanup tasks are attempted regardless of individual rejections, while still allowing the original critical error to be thrown.
**Action:** Always default to `Promise.all` for parallelizing independent I/O operations (like mapping arrays to asynchronous network calls) and specifically use `Promise.allSettled` in cleanup/rollback routines to prevent one failure from halting the entire cleanup process.

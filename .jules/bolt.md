## 2025-04-18 - Refactor Sequential I/O to Concurrent Promises in Service Layers
**Learning:** In backend-mimicking service files (like `supabaseService.ts`), multiple sequential I/O operations (like generating signed URLs or uploading multiple storage files in a `for...of` loop) are severe hidden bottlenecks, multiplying network latency by N. Furthermore, using sequential `await` in cleanup phases (e.g., reverting storage on DB insert failure) is dangerous because an early failure halts subsequent cleanup operations, leaving orphaned artifacts.
**Action:** Always favor mapping over arrays with `Promise.all` for independent parallel network requests (like uploads or signed URLs) to reduce total latency to O(1) regarding network wait time. For cleanup/rollback operations where completion of all tasks is critical regardless of individual failures, strictly use `Promise.allSettled`.
